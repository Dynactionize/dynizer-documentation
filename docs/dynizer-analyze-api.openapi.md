# Analyze API

The Analyze API is a Natural Language Processing (NLP) service that takes in documents and produces structured JSON results. You upload a file (PDF, Word, etc.), start an analysis, and retrieve the results — that's it. It does not manage files, workflows, or configurations.

## What it does

When you submit a document, the analyzer runs a full NLP pipeline that:

1. **Extracts text** from documents (PDF, Word, and more)
2. **Tokenizes** the text into individual words
3. **Detects sentences** and their boundaries
4. **Tags parts of speech (POS)** — identifying nouns, verbs, adjectives, etc.
5. **Parses syntax and dependencies** — understanding how words relate to each other grammatically
6. **Recognizes named entities (NER)** — picking out people, places, organizations, dates, etc.
7. **Resolves co-references** — linking pronouns like "he" or "it" back to the entity they refer to
8. **Extracts key concepts** — identifying the main topics and ideas in the text
9. **Matches against ontologies** — mapping extracted entities to known domain concepts
10. **Detects tone of voice** — analyzing sentiment and communication style

## How it works

- **Upload** a document via `POST /documents`
- **Start** an analysis via `POST /analyze`
- **Monitor** progress via `GET /analyze` or `GET /analyze/{id}`
- **Control** a running analysis (e.g. pause, cancel) via `PUT /analyze/{id}`
- **Delete** a completed or failed analysis via `DELETE /analyze/{id}`
Dynamically generate summaries
Generate action-WWWW structures without losing information
Interpret document formatting (recognizing, chapters, paragraphs, images, tables, columns, etc.)

The Dynizer Analyzer produces a json file with a fixed structured containing all the outpouts generated by the various functionalities. In other words, the structure is composed of Who/What/Where/When elements grouped into Actions.

## APIs

### Endpoint: /analyze

`GET /analyze`

Get the status and data of all analyze processes


***Parameters***

| Name | Type | Required | Description | Schema Reference |
|------|------|----------|-------------|-------------------|
| limit | integer |  | Defines how many records at max are returned. If fewer records are available, all will be returned. Omitting or setting this to -1 will be interpreted as no limit  | [Limit](#limit) |
| offset | integer |  | Defines the offset at which to start reading. An offset of 0 means to start from the first possible record.  | [Offset](#offset) |
  
  

**Responses**

+ `200`: 
        [GetAnalyzeResponse](#getanalyzeresponse)

    
 
+ `404`: 
        [404ErrorResponse](#404errorresponse)

    
 
+ `default`: 
        [DefaultErrorResponse](#defaulterrorresponse)

    
 
  
### Endpoint: /analyze

`POST /analyze`

Request processing from the analyzer.


  

**Responses**

+ `200`: 
        [PostAnalyzeResponse](#postanalyzeresponse)

    
 
+ `default`: 
        [DefaultErrorResponse](#defaulterrorresponse)

    
 
  
 
### Endpoint: /analyze/{id}

`GET /analyze/{id}`

Get the status and data of an analyze process


***Parameters***

| Name | Type | Required | Description | Schema Reference |
|------|------|----------|-------------|-------------------|
| id | string | True | ID of object to fetch. | [ID](#id) |
  
  

**Responses**

+ `200`: 
        [GetAnalyzeByIDResponse](#getanalyzebyidresponse)

    
 
+ `404`: 
        [404ErrorResponse](#404errorresponse)

    
 
+ `default`: 
        [DefaultErrorResponse](#defaulterrorresponse)
